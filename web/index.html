Target v1 architecture · activation pending

The service licenses the engine. Your runner builds the app.

Workload identity authorizes access to a specific immutable engine. Release verification and the build run on customer-controlled infrastructure, not in a hosted Envuscator build service.

  1. 01

    Identify the workload

    GitHub OIDC or GitLab job identity authenticates the CI execution.

  2. 02

    Authorize the engine

    The service checks the licensed scope and issues short-lived access.

  3. 03

    Verify and run

    The runner verifies signed release metadata and the exact private engine archive before execution.

  4. 04

    Keep the output

    Platform artifacts and evidence are generated locally without uploading customer builds.

Security boundary

Protection, not secrecy.

A determined attacker can inspect shipped application code and values. Build-specific obfuscation increases extraction effort; it does not replace backend authorization, encryption, secret rotation, or runtime security.

Commercial model

Licensing follows verified releases.

Subscription and one-time purchase options are intended, but checkout and production licensing are not yet live. Paid local/offline licensing requires its own authorization and recovery model; it is not a fallback from CI workload identity.
